## 📖 درباره افزونه

**Advanced WooCommerce Discount Code Generator** یک افزونه وردپرس/ووکامرس برای ایجاد کوپن‌های تخفیف انعطاف‌پذیر و قدرتمند با استفاده از سیستم تخفیف مبتنی بر قوانین است.

این افزونه سیستم استاندارد کوپن ووکامرس را توسعه می‌دهد و به مدیران فروشگاه اجازه می‌دهد چندین قانون تخفیف را در یک کوپن ایجاد کنند.

قوانین تخفیف می‌توانند محصولات مشخص، دسته‌بندی‌های محصولات، برندهای محصولات و سایر محصولات واجد شرایط را هدف قرار دهند.

## 🧠 نحوه عملکرد

این افزونه سیستم استاندارد کوپن ووکامرس را با یک موتور تخفیف انعطاف‌پذیر و مبتنی بر قوانین توسعه می‌دهد.

هر کوپن می‌تواند شامل چندین قانون باشد که موارد زیر را مشخص می‌کنند:

* محصولات مشمول تخفیف
* دسته‌بندی‌های مشمول تخفیف
* برندهای مشمول تخفیف
* نوع تخفیق
* مقدار تخفیف
* امکان اعمال تخفیف روی سایر محصولات واجد شرایط
* فعال یا غیرفعال بودن ارسال رایگان

### مثال

یک کوپن می‌تواند به‌گونه‌ای تنظیم شود که:

* 🟢 **۲۰٪ تخفیف** برای محصولات منتخب اعمال کند.
* 🔵 **۱۰٪ تخفیف** برای یک دسته‌بندی کامل محصولات اعمال کند.
* 🟣 یک **تخفیف مبلغ ثابت** برای محصولات یک برند مشخص اعمال کند.
* 🟠 تخفیف متفاوتی روی سایر محصولات واجد شرایط اعمال کند.
* 🚚 **ارسال رایگان** ارائه دهد.

تمام قوانین کوپن را می‌توان مستقیماً از پنل مدیریت وردپرس ایجاد، ویرایش و مدیریت کرد.

## 📦 نصب

### روش اول — نصب از طریق GitHub Release

1. به [آخرین نسخه](https://github.com/alirezasayadi/woocommerce-advanced-discount-builder/releases/latest) بروید.
2. فایل ZIP آخرین نسخه را دانلود کنید.
3. وارد پیشخوان وردپرس شوید.
4. به مسیر **افزونه‌ها ← افزودن افزونه ← بارگذاری افزونه** بروید.
5. فایل ZIP دانلودشده را انتخاب کنید.
6. افزونه را نصب کنید.
7. افزونه را فعال کنید.

قبل از استفاده از افزونه، مطمئن شوید که **WooCommerce** نصب و فعال باشد.

### روش دوم — نصب دستی

1. فایل ZIP آخرین نسخه را دانلود کنید.
2. فایل ZIP را استخراج کنید.
3. پوشه افزونه را در مسیر زیر آپلود کنید:

```text
/wp-content/plugins/
```

4. به **پیشخوان وردپرس ← افزونه‌ها** بروید.
5. افزونه **Advanced WooCommerce Discount Code Generator** را پیدا کنید.
6. روی **فعال‌سازی** کلیک کنید.

## 🚀 مدیریت انتشار نسخه‌ها

در این پروژه از **WPForge** استفاده نمی‌شود. پروژه **Advanced WooCommerce Discount Code Generator** دارای اسکریپت‌های اختصاصی برای خودکارسازی فرآیند انتشار نسخه در Git است.

این پروژه شامل دو اسکریپت انتشار است:

```text
scripts/
├── release.bat
└── release.sh
```

* `release.bat` — مخصوص Windows
* `release.sh` — مخصوص Linux و macOS

هر دو اسکریپت فرآیند انتشار یکسانی را انجام می‌دهند و برای یکپارچه نگه‌داشتن فرآیند انتشار در سیستم‌عامل‌های مختلف طراحی شده‌اند.

## 📋 پیش‌نیازهای انتشار

قبل از ایجاد یک Release، مطمئن شوید:

1. Git نصب شده و در `PATH` قرار دارد.
2. داخل پوشه پروژه هستید.
3. پروژه یک Git Repository است.
4. Remote با نام `origin` تنظیم شده است.
5. شاخه صحیح انتخاب شده است.
6. تغییرات شما آماده Commit هستند.
7. پروژه در وضعیت آماده برای انتشار قرار دارد.
8. شماره نسخه از قوانین Semantic Versioning پیروی می‌کند.

شاخه پیش‌فرض پیشنهادی:

```text
main
```

اگر روی شاخه‌ای غیر از `main` باشید، اسکریپت‌های انتشار به شما هشدار خواهند داد.

## 🪟 انتشار در Windows

کاربران Windows باید از فایل زیر استفاده کنند:

```text
scripts\release.bat
```

### 1. باز کردن Command Prompt

**Command Prompt (CMD)** را باز کرده و وارد پوشه پروژه شوید.

برای مثال:

```bat
cd D:\woocommerce-advanced-discount-builder
```

اگر پروژه در مسیر دیگری قرار دارد، می‌توانید مسیر مربوط به خودتان را وارد کنید.

### 2. اجرای اسکریپت انتشار

```bat
scripts\release.bat
```

اسکریپت شما را مرحله‌به‌مرحله در فرآیند انتشار راهنمایی می‌کند.

اسکریپت اطلاعات زیر را از شما دریافت می‌کند:

```text
Commit message:
Version:
```

برای مثال:

```text
Commit message: Release v1.0.1
Version: 1.0.1
```

همچنین می‌توانید نسخه را همراه با پیشوند `v` وارد کنید:

```text
v1.0.1
```

پیشوند به‌صورت خودکار مدیریت می‌شود و Tag نهایی به شکل زیر ایجاد خواهد شد:

```text
v1.0.1
```

### 3. بررسی شاخه

اسکریپت شاخه فعلی Git را بررسی می‌کند.

اگر روی:

```text
main
```

نباشید، هشدار زیر نمایش داده می‌شود:

```text
[WARNING] You are not on the main branch.
```

در این مرحله می‌توانید انتخاب کنید که فرآیند ادامه پیدا کند یا متوقف شود.

### 4. بررسی Remote

اسکریپت بررسی می‌کند که Remote با نام زیر وجود داشته باشد:

```text
origin
```

همچنین URL مربوط به Remote را قبل از ایجاد Release نمایش می‌دهد.

### 5. خلاصه انتشار

قبل از انجام هر تغییری، اسکریپت خلاصه انتشار را نمایش می‌دهد که شامل موارد زیر است:

```text
Branch
Version
Commit message
Remote
```

برای شروع عملیات Git باید انتشار را تأیید کنید.

## 🔢 نسخه‌بندی

نسخه‌های پروژه از **Semantic Versioning** استفاده می‌کنند:

```text
MAJOR.MINOR.PATCH
```

نمونه‌ها:

```text
1.0.0
1.0.1
1.1.0
2.0.0
```

Tagهای Git با پیشوند `v` ایجاد می‌شوند:

```text
v1.0.0
v1.0.1
v1.1.0
v2.0.0
```

### رفع خطا

برای رفع باگ‌هایی که با نسخه قبلی سازگار هستند:

```text
1.0.0 → 1.0.1
```

### قابلیت جدید

برای افزودن قابلیت‌های جدید که با نسخه قبلی سازگار هستند:

```text
1.0.0 → 1.1.0
```

### تغییر ناسازگار

برای تغییرات ناسازگار یا Breaking Change:

```text
1.0.0 → 2.0.0
```

تنها نسخه‌هایی با فرمت زیر پذیرفته می‌شوند:

```text
X.Y.Z
```

برای مثال:

```text
1.2.3
```

نمونه‌های نامعتبر:

```text
1.2
1.2.3.4
version-1.0.0
1.0
```

## 🔍 بررسی Tag

قبل از ایجاد Release، هر دو اسکریپت بررسی می‌کنند که نسخه موردنظر قبلاً ایجاد نشده باشد.

اسکریپت‌ها موارد زیر را بررسی می‌کنند:

### Tagهای محلی Git

```text
v1.0.0
```

### Tagهای Remote Git

```text
v1.0.0
```

اگر Tag موردنظر در سیستم محلی یا GitHub وجود داشته باشد، فرآیند انتشار متوقف می‌شود.

این کار از ایجاد مجدد یا بازنویسی تصادفی یک Release جلوگیری می‌کند.

اگر یک Tag در GitHub وجود دارد و عمداً قصد حذف آن را دارید، می‌توانید از دستور زیر استفاده کنید:

```bash
git push origin --delete v1.0.0
```

سپس فقط زمانی Release را مجدداً ایجاد کنید که از انجام این کار مطمئن باشید.

## 🔄 فرآیند انتشار

پس از تأیید انتشار، اسکریپت‌ها مراحل زیر را انجام می‌دهند.

### مرحله ۱ — افزودن فایل‌ها

تمام تغییرات Stage می‌شوند:

```bash
git add .
```

### مرحله ۲ — ایجاد Commit

اگر تغییراتی وجود داشته باشد، اسکریپت با استفاده از پیام Commit واردشده توسط شما، یک Commit ایجاد می‌کند.

برای مثال:

```text
Release v1.0.1
```

اگر تغییر جدیدی وجود نداشته باشد، اسکریپت بدون ایجاد Commit جدید ادامه می‌دهد.

### مرحله ۳ — Push کردن شاخه

شاخه فعلی به Remote با نام `origin` ارسال می‌شود.

برای تنظیمات استاندارد:

```bash
git push origin main
```

### مرحله ۴ — ایجاد Release Tag

یک Git Tag از نوع Annotated ایجاد می‌شود:

```text
v1.0.1
```

با پیام:

```text
Release v1.0.1
```

### مرحله ۵ — Push کردن Tag

Tag جدید به GitHub ارسال می‌شود:

```bash
git push origin v1.0.1
```

### مرحله ۶ — اجرای GitHub Actions

پس از ارسال Tag به GitHub، فرآیند Release به‌صورت خودکار توسط GitHub Actions آغاز می‌شود.

خود اسکریپت Release افزونه را Build نمی‌کند و GitHub Release را مستقیماً ایجاد نمی‌کند.

ادامه فرآیند انتشار توسط GitHub Actions انجام می‌شود.

## 🤖 فرآیند انتشار توسط GitHub Actions

پس از Push شدن Tag نسخه، GitHub Actions به‌صورت خودکار فرآیند Release را آغاز می‌کند.

این Workflow وظیفه انجام کارهایی مانند موارد زیر را بر عهده دارد:

1. اجرای بررسی‌های Syntax مربوط به PHP
2. اجرای تست‌های WordPress
3. نصب WordPress
4. نصب WooCommerce
5. فعال‌سازی افزونه
6. اجرای بررسی‌های زمان اجرا
7. ساخت فایل ZIP افزونه
8. ایجاد GitHub Release
9. آپلود فایل ZIP به‌عنوان Release Asset

می‌توانید وضعیت Workflow را از بخش زیر مشاهده کنید:

**GitHub → Actions**

یا مستقیماً از:

[GitHub Actions](https://github.com/alirezasayadi/woocommerce-advanced-discount-builder/actions)

## 📦 فایل‌های Release

پس از موفقیت‌آمیز بودن Workflow، GitHub Release شامل فایل تولیدشده افزونه خواهد بود.

فایل اصلی قابل دانلود، یک فایل ZIP شامل افزونه است.

برای مثال:

```text
woocommerce-advanced-discount-builder-v1.0.0.zip
```

نام دقیق فایل ممکن است بر اساس تنظیمات Workflow مربوط به GitHub Actions متفاوت باشد.

کاربران می‌توانند فایل ZIP را از مسیر زیر دانلود کنند:

**GitHub → Releases → Latest Release**

و سپس آن را از طریق مسیر زیر در وردپرس نصب کنند:

**پیشخوان وردپرس → افزونه‌ها → افزودن افزونه → بارگذاری افزونه**

## ⚠️ قوانین مهم انتشار

### GitHub Release را به‌صورت دستی ایجاد نکنید

هنگام استفاده از اسکریپت‌های انتشار، **نباید GitHub Release را به‌صورت دستی ایجاد کنید**.

فرآیند به شکل زیر به‌صورت خودکار انجام می‌شود:

```text
release.bat / release.sh
        ↓
Git Commit
        ↓
Push شاخه
        ↓
ایجاد Git Tag
        ↓
Push Tag
        ↓
GitHub Actions
        ↓
اجرای تست‌ها
        ↓
ساخت فایل ZIP افزونه
        ↓
ایجاد GitHub Release
        ↓
آپلود فایل ZIP
```

شما فقط باید اسکریپت انتشار را اجرا کرده و Release را تأیید کنید.

## ❌ اگر Release با خطا مواجه شد

اگر GitHub Actions با خطا مواجه شد:

1. وارد مخزن GitHub شوید.
2. به بخش **Actions** بروید.
3. Workflow ناموفق را باز کنید.
4. Job ناموفق را انتخاب کنید.
5. گزارش خطا را بررسی کنید.
6. مشکل را در سیستم خود برطرف کنید.
7. اصلاحات را Commit کنید.
8. یک نسخه جدید و مناسب ایجاد کنید.

برای مثال، اگر نسخه:

```text
v1.0.0
```

قبلاً منتشر شده و یک باگ برطرف شده است، از نسخه زیر استفاده کنید:

```text
v1.0.1
```

سعی نکنید همان نسخه را دوباره منتشر کنید، مگر اینکه عمداً Tag و Release موجود را حذف کرده و مجدداً ایجاد کنید.

## 🔁 فرآیند پیشنهادی انتشار

فرآیند پیشنهادی توسعه و انتشار به شکل زیر است:

```text
1. ایجاد تغییرات
       ↓
2. تست محلی
       ↓
3. بررسی افزونه
       ↓
4. اجرای release.bat / release.sh
       ↓
5. وارد کردن پیام Commit
       ↓
6. وارد کردن نسخه
       ↓
7. تأیید Release
       ↓
8. Git Commit
       ↓
9. Push شاخه
       ↓
10. ایجاد Git Tag
       ↓
11. Push کردن Git Tag
       ↓
12. شروع GitHub Actions
       ↓
13. اجرای تست‌های خودکار
       ↓
14. ساخت فایل ZIP افزونه
       ↓
15. ایجاد GitHub Release
       ↓
16. آپلود فایل ZIP
```

این فرآیند یک روش یکپارچه و خودکار برای انتشار نسخه در Windows، Linux و macOS فراهم می‌کند.

## 🧪 چک‌لیست انتشار

قبل از ایجاد یک Release جدید، موارد زیر را بررسی کنید:

* [ ] تمام تغییرات تکمیل شده‌اند.
* [ ] افزونه به‌درستی کار می‌کند.

* [ ] شاخه صحیح Git انتخاب شده است.
* [ ] پیام Commit واضح است.
* [ ] نسخه از فرمت `MAJOR.MINOR.PATCH` پیروی می‌کند.
* [ ] نسخه موردنظر قبلاً منتشر نشده است.
* [ ] Remote با نام `origin` تنظیم شده است.
* [ ] خلاصه Release بررسی شده است.
* [ ] Release تأیید شده است.
* [ ] GitHub Actions با موفقیت کامل شده است.
* [ ] فایل ZIP تولیدشده در GitHub Releases در دسترس است.

## 🛠️ اسکریپت‌های انتشار

پروژه شامل فایل‌های زیر است:

```text
scripts/
├── release.bat
└── release.sh
```

### Windows

```bat
scripts\release.bat
```

### Linux / macOS

```bash
chmod +x scripts/release.sh
./scripts/release.sh
```

هر دو اسکریپت برای ارائه یک فرآیند انتشار یکسان طراحی شده‌اند و در عین حال از استانداردها و conventions مربوط به سیستم‌عامل خود پیروی می‌کنند.
